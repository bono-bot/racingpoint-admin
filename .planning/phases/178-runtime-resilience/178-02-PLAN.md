**src/app/providers.tsx** (create new file):
- `'use client'` directive
- Import `SWRConfig` from `swr`
- Import `circuitBreaker` from `@/lib/api/base`
- Export `SWRProvider` component wrapping children in `SWRConfig`:
  - `value` prop with global SWR config:
    - `onError: (error: Error) => { /* no-op, let components handle */ }`
    - `shouldRetryOnError: false` — disable SWR's built-in retry since our API layer already retries with backoff. SWR retrying on top of our retry would cause excessive requests.
    - `dedupingInterval: 5000` — prevent duplicate requests within 5s
    - `errorRetryCount: 0` — reinforces no SWR-level retry
    - `keepPreviousData: true` — THIS IS KEY for RUNTIME-05: when a revalidation fails, SWR keeps showing the previous successful data instead of clearing it
    - `revalidateOnFocus: true` — revalidate when user returns to tab (good for recovery detection)
    - `onErrorRetry: (error, _key, _config, revalidate, { retryCount }) => { ... }` — custom retry that checks circuit breaker state:
      - If `circuitBreaker.getState() === 'open'`, do NOT schedule any retry (backend is confirmed down)
      - If state is 'half-open' or 'closed', schedule a retry after `Math.min(retryCount * 5000, 30000)` ms using setTimeout + revalidate (slow poll to detect recovery)
  - Wrap children: `<SWRConfig value={swrConfig}>{children}</SWRConfig>`
