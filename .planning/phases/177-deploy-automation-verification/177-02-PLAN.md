Rewrite `deploy-staging/deploy-nextjs.sh` as a complete deploy pipeline. Keep the existing app config structure (admin/kiosk/web case block) but add these capabilities:

**Script structure (8 steps):**

```
[1/8] Build locally (npm run build in SRC dir)
[2/8] Verify build output (server.js + .next/static + page count sanity)
[3/8] Package (copy .next/static into standalone, zip with PowerShell Compress-Archive)
[4/8] Pre-deploy health snapshot (curl existing /api/health on server, capture pages_before)
[5/8] Upload & Deploy (SCP zip to server, SSH to stop/extract/start)
[6/8] Health check (curl /api/health, check for "ok" status)
[7/8] Log deploy result to racecontrol
[8/8] Rollback if health check failed
```

**Key implementation details:**

A. **App config block** — keep existing but add:
   - `SERVICE_NAME` for each app (used in log messages): "racingpoint-admin", "racecontrol-kiosk", "racecontrol-web"
   - Admin and web both use PORT=3200 (admin replaces web when deployed)

B. **Step 4 — Pre-deploy health snapshot:**
   - `curl -s http://192.168.31.23:$PORT/api/health` and capture the response
   - Extract `pages_available` as PAGES_BEFORE using grep/sed (keep it simple, no jq dependency)
   - If the app is not currently running, set PAGES_BEFORE=0

C. **Step 5 — Upload & Deploy with backup:**
   - SCP the zip: `scp -o StrictHostKeyChecking=no "$ZIP_PATH" "$SERVER:C:/RacingPoint/$ZIP_NAME"`
   - SSH to server and run PowerShell that:
     1. Stops the node process on the target port (Get-NetTCPConnection to find PID)
     2. If the current app directory exists, zip it as backup: `Compress-Archive -Path '$REMOTE_DIR/*' -DestinationPath 'C:\RacingPoint\$APP-backup.zip' -Force`
     3. Remove old app directory
     4. Extract new zip to app directory
     5. Verify server.js and .next/static exist
     6. Set env vars (PORT, HOSTNAME=0.0.0.0, RC_URL=http://192.168.31.23:8080, RC_JWT_SECRET=UKLvoxSUMRPsKckeN17vJ-ORNgkTpfVO2MvS_JA5TMo)
     7. Start node with Start-Process (WindowStyle Hidden, redirect stdout/stderr to C:\RacingPoint\$APP-stdout.log and $APP-stderr.log)
   - Wait 5 seconds for app to start

D. **Step 6 — Health verification gate (DEPLOY-04):**
   - Retry health check up to 3 times with 5-second waits (app may need startup time)
   - `curl -s http://192.168.31.23:$PORT/api/health`
   - Parse response: check for `"status":"ok"` and `"healthy":true`
   - Extract `pages_available` as PAGES_AFTER
   - Extract `pages_missing` array content
   - If status is "ok" and healthy is true: DEPLOY_RESULT="success"
   - If status is "degraded" or healthy is false: DEPLOY_RESULT="failed"
   - If no response after retries: DEPLOY_RESULT="failed", set ERROR="health endpoint unreachable"

E. **Step 7 — Log to racecontrol (DEPLOY-05):**
   - Write JSON payload to a temp file (standing rule: no inline JSON in Git Bash)
   - Fields: app=$APP, result=$DEPLOY_RESULT, deployer="james", pages_before=$PAGES_BEFORE, pages_after=$PAGES_AFTER, pages_missing="$MISSING_PAGES", duration_secs=$DURATION, error="$ERROR", build_hash=$(git -C "$SRC" rev-parse --short HEAD)
   - `curl -s -X POST http://192.168.31.23:8080/api/v1/deploy-log -H "Content-Type: application/json" -d @$TMPFILE`
   - If racecontrol is unreachable, warn but don't fail the deploy (logging is best-effort)

F. **Step 8 — Auto-rollback (DEPLOY-06):**
   - Only runs if DEPLOY_RESULT="failed"
   - SSH to server:
     1. Stop the (broken) node process
     2. Remove the broken app directory
     3. Extract backup zip: `Expand-Archive -Path 'C:\RacingPoint\$APP-backup.zip' -DestinationPath '$REMOTE_DIR' -Force`
     4. Start node again with same env vars
   - Wait 5 seconds, re-check health
   - Log rollback to racecontrol: result="rollback"
   - Print clear message: "ROLLBACK COMPLETE — previous version restored"
   - Exit with code 1 (deploy failed even though rollback succeeded)

G. **Timing:**
   - Capture START_TIME at script start (`date +%s`)
   - Compute DURATION at end for deploy log

H. **Exit codes:**
   - 0 = success
   - 1 = deploy failed (with or without rollback)
   - 2 = build failed (before upload)

**Do NOT use:**
- `jq` (not guaranteed on Git Bash) — use grep/sed for JSON parsing
- Inline JSON in curl commands (standing rule) — always write to tmpfile first
- `python -m http.server` for upload — use SCP instead (simpler, no background process cleanup)
