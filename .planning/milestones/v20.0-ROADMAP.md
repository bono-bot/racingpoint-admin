# Roadmap: Admin Dashboard (v20.0)

## Overview

Build the unified operations dashboard for Racing Point eSports — staff authentication, fleet monitoring and control, billing session management, and shared infrastructure. This is the main operations program that gives staff a single authenticated dashboard for all daily ops.

## Phases

- [x] **Phase 159: Authentication & Session Security** - PIN pad login via RaceControl, JWT sessions, protected routes, role badges (completed 2026-03-22)
- [x] **Phase 160: Shared Infrastructure** - API client modularization, form library, icons, toast system (completed 2026-03-22)
- [x] **Phase 161: Fleet Monitoring** - Real-time pod health dashboard with status cards, SWR polling, activity log (completed 2026-03-22)
- [x] **Phase 162: Fleet Actions & Deployment** - Pod control (wake/shutdown/restart/lockdown), bulk actions, remote exec, deploy UI (completed 2026-03-22)
- [x] **Phase 163: Billing — Active Sessions** - Live session table with countdown, start/stop/pause/resume/extend actions, event timeline (completed 2026-03-22)
- [x] **Phase 164: Billing — Management** - Session history with filters, refund modal, daily reports, rate management (completed 2026-03-22)

## Phase Details

### Phase 159: Authentication & Session Security
**Goal**: Staff must log in before accessing any dashboard functionality; unauthenticated users see only the login page
**Plans**: 3 plans (auth foundation, middleware + proxy, PIN pad UI + AuthProvider)
**Key Artifacts**: jose JWT, Edge middleware, PIN pad, AuthProvider, session expiry warning

### Phase 160: Shared Infrastructure
**Goal**: Modular API client, form validation, icon system, and toast notifications as foundation for all feature phases
**Plans**: 3 plans (libraries + toast, API modularization, forms + icons)
**Key Artifacts**: Domain API modules (fleet, billing, drivers, events, games, ops), sonner toasts, zod forms, lucide icons

### Phase 161: Fleet Monitoring
**Goal**: Real-time pod health dashboard showing status, version, uptime, and activity log for all 8 pods
**Plans**: 2 plans (health dashboard, activity log)
**Key Artifacts**: Fleet page with pod cards, SWR polling, activity log with pod filter

### Phase 162: Fleet Actions & Deployment
**Goal**: Control individual pods and fleet-wide operations from the dashboard
**Plans**: 2 plans (pod actions + confirm dialog, deploy + remote exec)
**Key Artifacts**: Action buttons, bulk action bar, ConfirmDialog, deploy section, remote exec UI

### Phase 163: Billing — Active Sessions
**Goal**: Active billing sessions with real-time status and full lifecycle control
**Plans**: 2 plans (live sessions table, session actions + timeline)
**Key Artifacts**: Live billing page, countdown timers, start session modal, action buttons, event timeline

### Phase 164: Billing — Management
**Goal**: Historical billing data, refund processing, rate management, and daily reports
**Plans**: 2 plans (history + refunds, reports + rates)
**Key Artifacts**: History page with filters, refund modal, split view, daily reports, rate CRUD

## Deferred Requirements

The following PROJECT.md requirements are NOT covered by v20.0 phases 159-164:
- Drivers & Wallets (profiles, wallet management, memberships, badges)
- Events & Championships
- Game Management (launch/stop on pods, AC content browser)
- Scheduling & Operations (scheduler, ops dashboard)
- Data Migration (SQLite → RaceControl)
- Control Room Overview (mission control view)
- AUTH-05: Role-based access control gating (infrastructure built, no actual permission gates)

These are tracked for future milestones.
